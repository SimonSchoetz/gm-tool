# spec-writer Gate Extensions

Project-specific rows for `spec-writer-gates.md`'s Pre-Emission Compliance Pass, run in addition to that file's own table — same four-column shape, so rows relocate verbatim. On-demand rather than auto-loaded: large (several thousand characters of gate rows) and consumed by exactly one role at one step, unlike the facts in root `CLAUDE.md` that every role needs by default.

| Gate | Trigger | Check | Authority |
| --- | --- | --- | --- |
| Import trace | any relative import in the spec | anchor first: sibling-inside-grouping-folder rule vs. barrel rule; then trace each `../` from the importer's actual file, not a feature root | app/src/CLAUDE.md — Barrel Files |
| Bare HTML elements | `<input>`, `<button>`, or typed variants (`<input type="color">`) in examples | glob `app/src/components/` for name-match and semantic-match wrappers; read the wrapper's props before use | app/src/CLAUDE.md — UI primitive wrappers |
| Hook placement | any hook depending on a context provider | component renders below the provider — trace the tree, re-trace after moves | app/src/CLAUDE.md — providers/ |
| Helper extraction | a multi-statement body, or a single expression, reaches 2+ occurrences, including occurrences represented only via a substitution-table reference — trace the substitution table's reference file to determine the shape it produces rather than treating an un-reproduced body as invisible to this count | extract to `ComponentName/helper/` (multi-statement body) or to the nearest existing canonical location for the expression's layer (single expression); list every occurrence as a call site to update | app/src/CLAUDE.md — Component Library; root CLAUDE.md — duplicate-expression extraction |
| Sub-component extraction | near-identical JSX repeated 2+ times with only data-level variance | extract to `ComponentName/components/` | app/src/CLAUDE.md — Component Library |
| Memoization | any `useCallback`/`useMemo` in examples | qualifying reason stated at the call site (effect dependency or `React.memo` prop) — otherwise remove | app/src/CLAUDE.md — State Management |
| Async ownership | any Frontend layer entry places subscription/listener/async logic (e.g. `listen()`) in a component | cross-reference other Frontend entries and existing hooks for the same concern — screens and components own no async logic themselves | app/src/CLAUDE.md — TanStack Query pattern |
| Parent-type import | sub-component imports a type from its parent module | relocate the type to a neutral file both import from | app/src/CLAUDE.md — Component Library |
| Singleton-state scaffolding | 2+ tests call a function owning module-level singleton state | `vi.resetModules()` in `beforeEach` + dynamic imports per test — "scaffolding unchanged" or static imports is wrong | app/db/CLAUDE.md — Testing |
| Tunable-constant assertions | tests of geometry/layout helpers driven by constants under visual tuning | assert from the same imported constant the implementation uses — never a baked literal (literals stay correct for non-tunable outputs) | app/src/CLAUDE.md — Testing Policy |
| Untested residual risk | a construct is exempted from unit tests under the Testing Policy (React component) and its behavior falls in the category app/src/CLAUDE.md's Testing Policy names as untestable-by-policy residual risk (interaction-only behavior dependent on native browser default actions, invisible to helper/data-layer tests) | enumerate every risk in that category the construct carries — not only the first found — and state each one explicitly as its own manual-verification note in the sub-feature, prefixed with the literal marker `[MANUAL-VERIFY]` at the start of the line, naming the exact interaction to verify by hand; the Testing Policy exemption covers the absence of automated coverage, not the absence of risk, and covers it per risk, not per construct. The marker must appear verbatim, since `/implement`'s manual-verification risk scan greps for it deterministically. Separately — as a distinct output, never added to the marker's own line — when a risk exists because a specific structural choice guards against a failure mode a future edit could reintroduce undetected by review or tooling, add an instruction directing the implementer to write a named code comment at that exact construct stating the rationale and the failure mode; the marker records what to verify by hand, the comment records why the construct must stay shaped that way, and only the comment survives the spec's own deletion after implementation. This addition fires only within this gate's own trigger — a durable structural invariant with no accompanying `[MANUAL-VERIFY]` marker (e.g. a backend, service, or DB-layer invariant) is not reached here; treat a first such instance elsewhere as the signal to evaluate a broader rule, not as evidence to extend this one silently | app/src/CLAUDE.md — Testing Policy |
| Third-party runtime testability verification | a construct's Testing Policy exemption is justified by the claim that a third-party runtime executes it (e.g. a transformer or rule configuration handed to an external tool) | verify against the installed package tree (`node_modules`, `package.json`) whether that runtime is drivable headlessly without a component render before accepting the exemption — configuration handed to a third-party runtime is still first-party surface, and its testability is a dependency question to check, not a conclusion to assume from which system executes it. If the runtime is drivable headlessly: write the automated test when the construct's directory falls within Testing Policy's scope (`helper/`, `/src/util/`); if the construct sits outside that scope despite being technically testable, do not default to `[MANUAL-VERIFY]` — record the scope gap in the CLAUDE.md impact section instead, since a confirmed-testable construct with no owning test obligation is a Testing Policy gap, not a residual risk | app/src/CLAUDE.md — Testing Policy |
| cn() static-argument misuse | any `cn()` call in spec code examples | at least one argument must depend on a runtime condition (ternary, `&&`, a variable) — two or more static strings with no conditional is a misuse | app/src/CLAUDE.md — Component Internals (cn() usage — conditional and computed classes only) |
