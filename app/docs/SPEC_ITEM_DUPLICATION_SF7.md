# SF7 — `ScreensDuplicateBtn`

Creates the shared duplication control, its seven per-entity leaves, and the type augmentation that lets the focus signal travel as router navigation state.

The component has no consumer within this sub-feature. **SF8 wires it** into all eight item screen sidebars.

## Type augmentation

### `src/types/historyState.d.ts`

`HistoryState` is declared as an empty interface, so a navigation-state field is not type-permitted until the module is augmented:

```ts
export {};

declare module '@tanstack/history' {
  interface HistoryState {
    focusNameInput?: boolean;
  }
}
```

`export {}` is required — it makes the file a module, which is what turns `declare module` into an augmentation of the existing declarations rather than an ambient redeclaration that would replace them.

The file is picked up by `app/tsconfig.json`'s `"include": ["src", ...]` and needs no import anywhere. It is deliberately **not** added to `src/types/index.ts`: that barrel carries explicit named exports, and this file exports no value.

`@tanstack/history` is currently only a transitive dependency of `@tanstack/react-router`. Augmenting a module the app does not declare a direct dependency on is fragile across installs, which is why it is added to `dependencies`. Match the version already resolved in `app/node_modules/@tanstack/history/package.json` rather than picking a range independently.

`exactOptionalPropertyTypes` is enabled in `app/tsconfig.json`. Under that flag an optional property accepts omission or a `boolean`, but rejects an explicitly assigned `undefined` — so navigation calls that do not want the flag omit the key entirely rather than passing `undefined`.

## Frontend layer

### `ScreensDuplicateBtn.tsx`

**Purpose** — The single place that decides whether an entity can be duplicated and what its button is called. Placing it in every sidebar unconditionally means the duplicability rule lives in one switch instead of in eight remembered omissions.

**Behavior** — Takes one prop, `entityType: EntityType`, imported from `@domain`. Computes the label once as `` `Duplicate ${entityTypeLabel(entityType)}` `` and switches on `entityType`:

- `case 'adventures':` returns `null`. Adventures own seven child tables and their duplication is out of scope; this case becomes a component when that ships.
- The seven other cases each render their matching leaf, passing `label`.

The switch is exhaustive over `EntityType`, so no `default` branch is written. Every case returns, satisfying `noFallthroughCasesInSwitch`.

The label is computed here rather than in each leaf so `entityTypeLabel` is called once instead of being restated across seven files.

Use `FCProps<Props>` with a named `type Props` per `app/src/CLAUDE.md`'s props pattern — case 3, since the root node is neither a native element nor a specific existing component.

**UI / Visual** — Renders nothing of its own; it returns whichever leaf the switch selects, or `null`.

### `components/<Entity>DuplicateBtn.tsx`

**Purpose** — Owns the duplicate action for one entity type. Seven near-identical files, structurally modelled on `BreadcrumbList/components/NpcCrumb.tsx`: a flat per-entity file that calls its own hook.

Separate files are structurally required, not stylistic. A single component cannot call `useNpc` versus `usePc` off a runtime prop, and a single shared hook cannot reach the per-module query key factories that invalidation needs, because `app/src/CLAUDE.md` keeps those out of module barrels.

**Behavior** — Takes one prop, `label: string`.

Reads its route params with `useParams({ from: '<its own detail route>' })` — the typed form the sidebars already use, valid because a leaf only ever renders on its own route. This differs from `NpcCrumb`'s `{ strict: false }`, which that file needs because `BreadcrumbList` renders on every route.

Calls its `use<Entity>` hook for `duplicate<Entity>`, then on click:

1. `const newId = await duplicate<Entity>();`
2. `await navigate({ to: buildEntityPath('<plural>', newId, adventureId), state: { focusNameInput: true } });`

`buildEntityPath` comes from `@domain`. Passing its string result as `to` is the pattern `MentionPopup.tsx` already uses with the same helper.

`state` accepts the object form directly. The augmentation from this sub-feature is what makes `focusNameInput` assignable.

The click handler is wired as `onClick={() => { void handleDuplicate(); }}` — the wrapper is required by `@typescript-eslint/no-misused-promises` to discard the promise where a synchronous callback is expected, which `app/src/CLAUDE.md` names as a permitted wrapper.

No try/catch. Errors from the mutation reach the Error Boundary through the QueryClient's `throwOnError` default.

**UI / Visual** — Renders `<Button label={label} onClick={...} />` from `@/components`, with no `buttonStyle` prop so it takes the default treatment. `buttonStyle` is reserved for `'danger'`, which the sibling Delete buttons use; a duplicate action is not destructive.

## Substitution table

`NpcDuplicateBtn.tsx` is the reference. The other six are pure name substitution.

| Token | NPC | PC | Foe | Faction | Location | Item | Session |
| --- | --- | --- | --- | --- | --- | --- | --- |
| Component | `NpcDuplicateBtn` | `PcDuplicateBtn` | `FoeDuplicateBtn` | `FactionDuplicateBtn` | `LocationDuplicateBtn` | `ItemDuplicateBtn` | `SessionDuplicateBtn` |
| Hook | `useNpc` | `usePc` | `useFoe` | `useFaction` | `useLocation` | `useItem` | `useSession` |
| Hook fn | `duplicateNpc` | `duplicatePc` | `duplicateFoe` | `duplicateFaction` | `duplicateLocation` | `duplicateItem` | `duplicateSession` |
| Route `from` | `/adventure/$adventureId/npc/$npcId` | `.../pc/$pcId` | `.../foe/$foeId` | `.../faction/$factionId` | `.../location/$locationId` | `.../item/$itemId` | `.../session/$sessionId` |
| Param | `npcId` | `pcId` | `foeId` | `factionId` | `locationId` | `itemId` | `sessionId` |
| `buildEntityPath` arg | `'npcs'` | `'pcs'` | `'foes'` | `'factions'` | `'locations'` | `'items'` | `'sessions'` |
| Switch case | `'npcs'` | `'pcs'` | `'foes'` | `'factions'` | `'locations'` | `'items'` | `'sessions'` |

Each hook takes `(entityId, adventureId)` in that order — confirm against the hook's own signature before writing the call.
