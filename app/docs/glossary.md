# Glossary

Terms the feature pages in `features/` use. The entity vocabulary grounded in the database schema — base entity, content section and the rest — is the Domain Glossary in `app/CLAUDE.md`.

- **Basic stat block** — A content-section type (`basic-stat-block`) of a base entity: an HP number field with a text editor underneath, stored together as one JSON value in the section's content. See `features/basic-stat-block.md`.
- **5e stat block** — A content-section type (`5e-stat-block`) of a base entity: fixed saved fields for a foe's 5e stats, stored together as one JSON value in the section's content. See `features/five-e-stat-block.md`.
- **HP** — In a basic stat block, the creature's hit points as written in its stat block: empty or a whole number, negatives included. It is not current HP or damage taken during an encounter.
- **Web mode** — The app run in a plain browser by `pnpm run web` (or the `web` launch configuration) against a copy of the installed release app's data, with every Tauri call answered by the dev data server; a development tool for agent sessions and the developer, never in a release build. See `features/web-dev-mode.md`.
- **Dev data server** — The Vite plugin that, in web mode, copies the Tauri dev app's database and images into a temporary folder at every start, runs the checkout's pending migrations on the copy, and serves SQL, images and every Tauri command under `/__dev-data` on Vite's own origin.
- **Platform module** — `app/platform/`, the one place every Tauri call goes through: its Tauri implementation forwards to the Tauri packages, its web implementation talks to the dev data server, and the barrel picks one by Vite's mode.
- **Fixture image** — One of three small committed images (a landscape PNG, a portrait JPEG, a square WebP) the web-mode file picker hands out in file-name order in place of a native dialog.
- **Dev data mirror** — The first half of the `dev` script: before `tauri dev` starts, it replaces the Tauri dev app's database and images with a fresh copy of the installed release app's data, keeping the dev app's own preserved set. See `features/dev-data-mirror.md`.
- **Preserved set** — The rows the dev data mirror keeps from the old dev database instead of taking them from the release data: the `paired_devices` table, the `_sync_peers` table and the `_system` row `device`, which together are the dev app's own device identity and paired devices.
- **Content section carousel** — Stepping through a base entity's content sections one at a time with up/down buttons, on the entity screen and in the mention popup, each switch sliding vertically. See `features/section-carousel-mention-click.md`.
- **Click-opened popup** — A mention popup opened by clicking its badge, as opposed to a hover popup (opened by hovering, closed on pointer leave) and a pinned popup (kept until closed). It closes on a click outside it or on Escape, and Pin turns it into a pinned popup.
- **Mention anchor** — The position a mention popup was opened at, and the `data-mention-anchor` attribute on a badge carrying its entity id; a click on a badge of the popup's own entity never dismisses the popup, and a click on another badge of that entity moves it.
- **Content section body** — The component that renders one content section's content: `ContentSectionBody` picks the body of the section's type (text, basic stat block, 5e stat block) and is used editable by the base entity screen's panel and read-only by the mention popup. See `features/content-section-bodies.md`.
- **Queue item** — One row of an encounter's queue (`encounter_queue_items`): its kind (`combatant` or `event`), the base entity it was made from, the name stored when it was added, its sequence number, its starting max HP and its position. An event and a random combatant are queue items too: an event's `name` is its own, and a random combatant's is the typed name, with no base entity. See `features/encounter-queue.md`.
- **Combatant** — A queue item of kind `combatant`: one fighter in the encounter, either made from a base entity by an Add and shown with the entity's image and HP and its shown name as the entry's tooltip, or a random combatant with a typed name and an optional HP. It also carries a combat name, the GM's rename of it, and its own notes.
- **Random combatant** — A combatant added from the Add tab's Other / Random Combatant form with a typed name, an optional HP and a quantity, and no base entity: it shows the image placeholder, is numbered among the combatants of the same typed name, and has no entity view.
- **Event** — An encounter event: a queue item of kind `event` with a name and notes, no HP and no numbering, drawn in the queue with an icon tile in the image's place, never hidden by Hide defeated. It is added from the Add tab's Other / Event form, and an emptied name shows "Untitled Event".
- **Shown name** — The name a combatant displays: its combat name when the GM gave it one, without a number; otherwise the linked entity's current name ("Untitled Combatant" when it has none), or the name stored on the queue item once the entity is gone, followed by its sequence number while the entity has more than one combatant in the encounter.
- **Sequence number** — The number a combatant carries among the combatants of the same entity in one encounter ("Goblin 2"), a random combatant among the combatants of the same typed name ("Grunt 2"); each Add continues from the highest number the entity or the name has there, and a number is never reused to close a gap. An event has none.
- **HP tint** — The overlay on a combatant's image: red from the bottom up over the share (max − current) / max of max HP that is missing, or grey instead at current HP 0 or below; absent while the combatant's HP is not set. A defeated combatant's image is grey whatever its HP, in place of the tint.
- **Encounter sidebar** — The right column of the encounter screen: an Add tab, an Actions tab and a Log tab drawn like browser tabs, the Add tab open when the encounter opens. The Add tab starts with an Entities / Other switch: Entities lists the adventure's base entities with a type filter and a search and adds combatants of the chosen entity, and Other holds an Event / Random Combatant switch with the form that adds an event or random combatants; the Actions tab acts on the selected combatants and removes selected events; the Log tab shows the combat log.
- **Combat log entry** — One row of an encounter's combat log (`encounter_log_entries`), with a kind and a JSON payload. Each Add writes one `added` entry listing the queue item ids it added, each action of the Actions tab, for one combatant or several, writes one `damage`, `heal`, `temp-hp`, `max-hp`, `defeated`, `undefeated` or `removed` entry, each Revert writes a `revert` entry naming the entry it reverts, and each send of the composer writes a `message` entry; a combatant's HP, defeated mark and removal are derived from the entries, minus the ones a revert drops. The Log tab shows the entries.
- **Log tab** — The third tab of the encounter sidebar: every entry of the combat log, oldest at the top and scrolled to the newest, each with its time, and at the bottom a composer for typed messages. It opens only on a click on its tab. See `features/encounter-log.md`.
- **Revert** — The button on a revertible log entry (Damage, Heal, Temp HP, Max HP, Defeated, Undefeated, Removed) that is not yet reverted: one click writes a `revert` entry, and the fight's values become what they would be had the entry never happened. The reverted entry stays in the log, struck through, and loses its button.
- **Typed message** — A `message` entry the GM writes in the Log tab's composer: text, line breaks and @mentions of entities, sent with Enter, shown as a chat bubble and deletable with its own Delete button; the only kind of log entry that can be deleted.
- **Global combat notes** — The encounter's description editor, shown at the top of the encounter screen's middle column; the shown item's view sits below it.
- **Selection** — The set of queue entries, combatants and events, a click on queue entries selected, each shown with the app's active highlight: a click selects only the clicked entry, Cmd/Ctrl-click toggles one, Shift-click selects the shown range from the anchor. The Actions tab acts on them, Escape clears the selection, the anchor and the shown item except while focus is in an editable element of the middle column, and an entry that is removed or hidden leaves it. Nothing is selected when the encounter opens.
- **Shown item** — The selected queue entry whose view the encounter screen's middle column shows below the global combat notes: for a combatant its combat name, HP, own notes and its entity's content sections and description; for an event its name field and notes, with no HP and no entity view. A click, a Cmd/Ctrl-click that adds and a Shift-click make an entry the shown item; nothing is shown when the encounter opens.
- **Combat name** — The GM's rename of one combatant, stored as `custom_name` on its queue item: shown without a number in the queue, the Actions tab and the log lines naming that combatant, never in the "Added" line. Emptying it, or typing exactly the automatic name, removes it.
- **Automatic name** — The name a combatant shows while the GM gave it no combat name: the shown name without a rename, numbered while the entity has more than one combatant in the encounter. Typing exactly this name, or emptying the name field, stores no rename.
- **Entity view** — The part of the shown combatant's view below its notes that shows its entity's content section panel and description editor, editable as on the entity's screen; a combatant whose entity was deleted has none.
- **Anchor** — The queue entry last clicked without Shift; a Shift-click selects the shown entries from the anchor to the clicked entry, and a further Shift-click ranges from the same anchor. Without an anchor, or with its anchor removed or hidden, a Shift-click selects only the clicked entry and anchors it.
- **Block drag** — Dragging a selected queue entry by its handle moves every selected entry as one block to the drop position, keeping their order; while it is held the other selected entries leave the list and the dragged entry shows a "+N" badge. Dragging an unselected entry moves only that entry.
- **Group action** — An action of the Actions tab applied to every selected combatant it can change, written as one combat log entry that lists every target with its own amount or value; the others are skipped.
- **Shared amount** — The amount field above the Actions tab's buttons, shown from two selected combatants on, selected events never counting: typing in it fills every row's own amount field, which can then be changed on its own.
- **Defeated** — A mark on a combatant set by Mark defeated and cleared by Unmark defeated, independent of its HP; a defeated combatant's image is grey and the entry is not dimmed.
- **Hide defeated** — A box under the encounter's queue that hides defeated combatants while checked; it is saved per encounter, and a hidden combatant keeps its place in the queue.
- **Duplicate** — The button below the encounter's queue that creates a new encounter named as before, with the source's global combat notes and Hide defeated setting and a copy of every queue item the source has not removed, in the same order and with the same names and notes, each combatant at full HP and not defeated; the copy's combat log starts empty.
- **Amount** — The whole number of 0 or more typed into a selected combatant's row in the Actions tab, or into the shared amount, which Damage, Heal, Set temp HP and Set max HP apply to that combatant; each row keeps its amount after an action while its combatant stays selected.
- **Cover** — The image of an encounter, stored as its `image_id`, set and replaced with a 200 × 200 upload control at the top of the encounter screen's left column and shown in the first column of the encounters list; also the label of every table list's image column. An entity with no image shows the placeholder icon of its domain instead. See `features/encounter-queue.md`.
