# Content section bodies

**Purpose.** The GM sees a content section the same way in both places that show it: editable on the base entity's screen, read-only in the entity's mention popup. Each section type (Text, Basic Stat Block, 5e Stat Block) has one body component of its own, used by both, so the popup shows exactly what was written in the panel and no separate "summary" slot bends each type into text with a header.

## How it works

Happy path:

1. On a base entity's screen, the content panel shows the selected section through its type's body: a Text and a 5e Stat Block section as a text editor, a Basic Stat Block as the HP number field with the text editor underneath. Editing and autosaving work as before.
2. In the entity's mention popup, the selected section is shown through the same body, read-only and laid out as on the screen. A Text and a 5e Stat Block section show their text; a Basic Stat Block shows "HP" and its value in a read-only field, then the text, with no indent on the HP row.
3. The entity's image stays beside the section region in the popup; stepping between sections (burger, up/down) slides only the section region.
4. The Session popup shows the session's summary and the Encounter popup the encounter's description, read-only, as before.

Failure:

- A section with no content shows the editor's placeholder on the screen and nothing in the popup.
- An entity with no sections shows the image alone in the popup.

Where the user waits: nothing new; the popup shows only its header until the entity's sections have loaded (see `section-carousel-mention-click.md`).

## Data

- **Reads:** the entity's content sections — type, name and content — from the cache every body shares; a section opened in the popup shows the screen's latest saved content.
- **Writes:** only the panel's editable bodies write, exactly as before (a text body its content; a Basic Stat Block its HP and text together, see `basic-stat-block.md`). The popup writes nothing.
