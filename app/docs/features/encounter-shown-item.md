# Encounter shown item

**Purpose.** The encounter screen's middle column shows the clicked queue entry below the global combat notes: a combatant with its editable combat name, read-only HP, own notes and its entity's editable content sections and description, or an event with its name and notes. The Data, Open points and Where to look sections for the whole encounter screen are on [Encounter queue](encounter-queue.md).

**Users.** The GM, as everywhere in the app.

## How it works

Happy path:

1. With nothing shown, the middle column reads "Click an entry in the queue to show it here." below the global notes.
2. With a combatant shown, the middle column below the global notes starts with a name field showing the name the queue shows ("Goblin 3"). Typing another name renames this combatant only: the queue entry, its Actions tab row and every Log line naming that one combatant show the typed name, without a number, instantly as the GM types, and the database write follows about 0.5 s later. The "Added" line keeps the entity's name ("Added: Goblin ×5"). Emptying the field, a name of spaces only, or typing exactly the automatic name returns the combatant to its automatic name, numbered as before. Leaving the field or pressing Enter restores the shown name in the field. A renamed combatant still counts for its siblings' numbers: renaming "Goblin 1" to "Boss" leaves the other showing "Goblin 2". A rename writes no log entry.
3. Below the name the HP shows read-only as the queue shows it (`4 / 7`, `4 / 7 +2`), followed by a muted "Defeated" label while the combatant is marked defeated. It changes only through the Actions tab. A combatant whose HP is not set shows a sentence instead: "HP is not set: the entity has no stat block with an HP value. Set max HP in the Actions tab." when its entity has no stat block section or its one stat block has an empty HP; "HP is not set: the entity has more than one stat block. Set max HP in the Actions tab." when it has two or more; "HP is not set. Set max HP in the Actions tab." otherwise, when the stat block changed after the add or the entity was deleted. The entity's sections are read now, not at the moment of the add, and while they load a linked combatant shows no sentence.
4. Below the HP a notes editor with the placeholder "Combatant notes..." takes text and @mentions as the app's other notes editors do. Its text belongs to this combatant only: Goblin 3's notes are not Goblin 1's and do not appear on the Goblin entity. A note writes no log entry.
5. Below the notes, a combatant whose entity exists shows the entity's content section panel and description editor, editable exactly as on the entity's screen: adding, renaming, deleting and stepping through sections, editing a section's body, editing the description. An edit there changes the entity itself, so the entity's screen, its mention popup and every combatant of that entity, in this and other encounters, show it. A combatant whose entity was deleted shows its name, HP, defeated label and notes, and no entity view.
6. The global notes keep their fixed-height panel at the top. Everything below it, from the name field to the end of the description, scrolls as one area: the combatant notes and the description grow with their text, and the content section panel shows unchanged, as on the entity screen, so a section body keeps its own height and inner scroll.
7. A shown random combatant shows its name field ("Combatant name"), its HP and "Defeated" label and its notes editor ("Combatant notes..."), with no entity view; with HP not set it reads "HP is not set. Set max HP in the Actions tab.". A shown event shows a name field labelled "Event name" with the event's name and a notes editor with the placeholder "Event notes..." that takes text and @mentions, with no HP and no entity view. Typing renames the event in the queue and in every log line naming it, instantly as the GM types, and the database write follows about 0.5 s later. A field emptied, or holding spaces only, keeps what was typed, with "Untitled Event" as the greyed placeholder of an empty field, and leaving it fills nothing in; the event is saved with no name, and the queue and the log show "Untitled Event". A rename and the notes write no log entry and survive leaving the encounter and restarting the app.

Failure:

- A quit within about 500 ms of the last keystroke in the name field or the notes loses that edit, since both save through the encounter's autosave.
