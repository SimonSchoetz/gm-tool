# Sub-feature 1: Boundary and cycle lint rules

Adds the two lint rules that replace barrel conventions with enforcement: `local/no-import-past-index`, a new local rule, and `import-x/no-cycle`. Both run at `warn`, so every check keeps passing while SF2–SF5 restructure the tree. SF6 promotes them to `error` (root Key Architectural Decisions — "Both rules land at `warn` and are promoted to `error` last").

## Layered breakdown

No layer from the layer order is touched. Every file here is ESLint tooling under `app/`.

### Tooling — `app/eslint-rules/no-import-past-index.js`

An ES module (the project is `"type": "module"`, so a local rule must use `export default` — `.claude/knowledge/eslint.md` — `## Flat config local/inline plugin rules require ESM \`export default\`…`), starting with `// @ts-check` like `no-wrapped-line-comments.js`. It imports `node:fs`, `node:path` and `typescript` (already a devDependency, `~6.0.3`). Its only importers are `app/eslint.config.js` and its own test.

Exports:

- **Named export `findCrossedBoundary({ importerPath, targetPath, isBoundary, passThroughDirs })`**, returning the absolute path of the outermost crossed boundary folder, or `null`. All paths are absolute. `isBoundary(dir)` returns whether `dir` holds a file named `index.ts`, and `passThroughDirs` is an array of absolute folder paths. Algorithm:
  1. Start with `dir = path.dirname(targetPath)`.
  2. While `importerPath` does not start with `dir + path.sep`, and `dir` is not the filesystem root: if `isBoundary(dir)`, `dir` is not in `passThroughDirs`, and `targetPath !== path.join(dir, 'index.ts')`, record `dir` as the latest crossing. Then set `dir = path.dirname(dir)`.
  3. Return the last recorded crossing (the outermost), or `null`.
- **Named export `isBoundaryDir(dir, fileExists)`**, returning `fileExists(path.join(dir, 'index.ts'))`. `create` builds its cached `isBoundary` from it with `fs.existsSync`, so the marker file name lives in one function. `findCrossedBoundary` compares `targetPath` against the same `path.join(dir, 'index.ts')` form.
- **Default export: the rule object.**
  - `meta.type: 'problem'`.
  - `meta.docs.description`: `'Disallow importing a file behind another folder\'s index.ts; import that index.ts instead.'`
  - `meta.schema`: one object with property `passThroughDirs` (array of strings) and `additionalProperties: false`.
  - `meta.messages.pastIndex`: `"'{{specifier}}' reaches past {{boundary}}/index.ts. Import from that index.ts instead."`
  - `create(context)`:
    - Read `context.sourceCode.parserServices?.program`. When it is missing or `null` (a file linted without type information, see `.claude/knowledge/eslint.md` — `## With type information, typescript-eslint parser services carry \`program: ts.Program\`…`), return `{}`.
    - Otherwise take `compilerOptions = program.getCompilerOptions()`, and keep a per-`create` `Map` caching `isBoundaryDir(dir, fs.existsSync)` as `isBoundary`.
    - Visit `ImportDeclaration`, `ExportNamedDeclaration` and `ExportAllDeclaration` nodes that have a `source`, and `ImportExpression` nodes whose `source` is a string `Literal`.
    - For each, call `ts.resolveModuleName(specifier, context.filename, compilerOptions, ts.sys)`. Skip when `resolvedModule` is `undefined` or `resolvedModule.isExternalLibraryImport` is `true` (`.claude/knowledge/typescript.md` — `## \`ts.resolveModuleName\` is typed to return \`resolvedModule: ResolvedModuleFull | undefined\`…`).
    - Otherwise call `findCrossedBoundary` with `resolvedModule.resolvedFileName`. When it returns a folder, report on the `source` node with `messageId: 'pastIndex'`, where `boundary` is `path.relative(context.cwd, folder)`.
  - Type-only imports are checked like value imports: a type behind a boundary is as private as a value.

### Tooling — `app/eslint.config.js`

- Add imports:
  - `path` from `'node:path'`
  - `{ importX }` from `'eslint-plugin-import-x'`
  - `{ createTypeScriptImportResolver }` from `'eslint-import-resolver-typescript'`
  - `noImportPastIndex` from `'./eslint-rules/no-import-past-index.js'`

  The package exports are recorded in `.claude/knowledge/eslint.md`.
- In the existing config object that registers `local`:
  - Add `'no-import-past-index': noImportPastIndex` to `local.rules`, and add `'import-x': importX` to `plugins`.
  - Add `settings: { 'import-x/resolver-next': [createTypeScriptImportResolver({ project: path.resolve(import.meta.dirname, 'tsconfig.json') })] }`.
  - Add rules `'local/no-import-past-index': ['warn', { passThroughDirs: [path.resolve(import.meta.dirname, 'domain')] }]` and `'import-x/no-cycle': ['warn', { ignoreExternal: true }]`.

  `import.meta.dirname` keeps both paths independent of the directory ESLint runs from. The installed Node is v22.23.2, where it is available.
- Change the JS-files override's `files` entry `'eslint-rules/*.js'` to `'eslint-rules/**/*.js'`, so the new test file is linted without type information like the rule files.

Before and after this change, run `time npx eslint .` from `app/` and state both durations in the handoff. `no-cycle` is documented as expensive, and the user decides whether the difference is acceptable.
